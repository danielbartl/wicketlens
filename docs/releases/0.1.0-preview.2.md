# WicketLens 0.1.0 Preview 2

Preview 2 adds plain-Wicket test planning, read-only test-plan tools for agents,
and runnable workflows for adapting WicketTester scaffolds into behavior tests.
Existing component exploration, Java/HTML navigation, inspections, ID editing
and Spring analysis remain available.

## Download and install

1. Download **wicketlens-0.1.0-preview.2.zip** from this release's **Assets**.
   Keep it zipped. Use the plugin ZIP for installation; GitHub's source archives
   are for building from source.
2. In IntelliJ IDEA, open **Settings → Plugins → ⚙ → Install Plugin from Disk…**
   and select the ZIP. Restart if prompted. Install it the same way to update
   an existing Preview 1 installation.
3. Open your Wicket project and **View → Tool Windows → WicketLens**, or select
   a page/panel and choose **Tools → Generate Wicket Test…**.

The plugin version is **0.1.0-preview.2** and its release tag is
**v0.1.0-preview.2**. No local build or separate JDK installation is needed to
install the ZIP. The accompanying **SHA256SUMS.txt** identifies the exact archive.
WicketLens is not on JetBrains Marketplace yet.

## New since Preview 1

- **Plain-Wicket planning:** WicketTester/JUnit scaffolds for pages and panels
  without Spring or Mockito. Constructor strategies, explicit manual hooks,
  preview/copy/create, collision guards and undo share the existing machinery.
- **Two new read-only MCP tools:** `wicket_get_test_plan` handles plain Wicket
  and selects the existing Spring recipe when injection/application intent is
  recognized; `wicket_get_spring_test_plan` retains its Spring-specific gate.
  WicketLens now contributes **eight tools** to the native IDE server.
- **Agent-assisted workflows:** reusable prompts and portable examples show
  normal agent editing/testing tools adapting the returned scaffold. Examples
  cover page parameters, components, multiple named mocks, generic bindings,
  constructor arguments and custom session setup.
- **Behavior and regression checks:** demo tests assert rendered values and
  escaping; a reusable verifier introduces a deliberate change only in a
  disposable copy, requires assertion failures, restores it and requires passes.
- **Shared-generator fixes:** use exact field source identity for colliding
  main/test class names and track dependency types consulted for mock preparation.

See [test planning](https://github.com/danielbartl/wicketlens/blob/v0.1.0-preview.2/docs/wicket-test-planning.md),
[agent setup](https://github.com/danielbartl/wicketlens/blob/v0.1.0-preview.2/docs/mcp-client-setup.md),
the [plain demo](https://github.com/danielbartl/wicketlens/tree/v0.1.0-preview.2/examples/plain-test-demo),
and the [complex Spring workflow](https://github.com/danielbartl/wicketlens/blob/v0.1.0-preview.2/examples/spring-test-demo/COMPLEX_WORKFLOW.md).

## Verification and scope

- Verified baseline: **IntelliJ IDEA 2026.2.3**, build **IU-262.10968.63**, with
  **Apache Wicket 10.11.0** fixtures. Other IDE/framework combinations remain unverified.
- **1,749 normal tests**, **seven actual MCP-host tests**, and **20 release-checker
  tests** pass. Packaging/project/structure checks pass. Binary verification is
  **Compatible**, with four deprecated and six experimental API notices.
- Graphical checks cover sidebar analysis, the plain-test preview, native MCP
  enablement and all eight exposed tools. Codex CLI **0.166.0** and Claude Code
  **2.1.314** invoke the general planner successfully through that graphical server.
  The sandbox JAR matches the release ZIP; this is not a fresh installation in a
  normal user profile.
- The exact MCP-produced plain page/panel scaffolds compile/run without Spring
  or Mockito. Adapted plain tests pass three cases, and the Spring demo passes
  eight; controlled greeting/price changes cause the expected failures and
  restoration passes. This is portable-fixture verification, not production
  application evaluation.
- Test plans are scaffolds requiring review. Requirements are not dependency-
  availability findings; constructor/application setup, mock behavior and manual
  bindings remain explicit. MCP tools do not write files or execute tests.
- Analysis stays static and bounded. Runtime values, active Spring profiles and
  production wiring are not established by a completed request.
- Native MCP wire cancellation still does not promptly stop tool work in the
  verified host. WicketLens applies a **30-second deadline**; reconnect after
  session expiry. See [host limitations](https://github.com/danielbartl/wicketlens/blob/v0.1.0-preview.2/docs/mcp-isolation-transport.md).
  Connected agents may send tool responses to their model provider.
- Representative real-application accuracy/performance evaluation remains deferred.
