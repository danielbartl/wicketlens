# WicketLens 0.1.0 Release Candidate 1

RC 1 freezes the feature scope for the first 0.1.0 release. It brings together
component exploration, Java/HTML navigation and editor feedback, conservative ID
editing, optional Wicket–Spring inspection/dependency tools, test scaffolding,
Mounted URLs, and nine read-only MCP tools. Please report reproducible problems
with analysis, editing, installation or responsiveness before the final release.

## Installation and upgrade

Download **wicketlens-0.1.0-rc.1.zip** and its **SHA256SUMS.txt** from this
release's Assets. Install the ZIP without extracting it through
**Settings → Plugins → ⚙ → Install Plugin from Disk…**, then restart if prompted.
The same steps upgrade Preview 2. No local build or separate JDK is required.
WicketLens is not on JetBrains Marketplace yet.

## Changes since Preview 2

- Broader bounded Java analysis for agreeing if/else and ternary component
  structure, computed IDs, stable boolean predicates, and integral comparisons
  with per-input bounds and exclusions. Optional or conflicting setup stays
  conditional; unsupported effects retain explicit uncertainty.
- Queue placement and repeater item templates merge across reviewed branches,
  retaining parent scope, source origins and conservative editing guards.
- A project-wide **Mounted URLs** tab discovers mountPage declarations, reviewed
  source init inheritance, explicit super calls, and private/final no-argument
  helpers. Inline mount(new MountedMapper(...)) registrations retain page/HTML
  navigation, explicit encoder notes and supplier/anonymous uncertainty.
- **wicket_get_routes**, the ninth MCP tool, exposes the same route snapshots,
  application/module/source-set filters, locations, status and coverage notes.
  Existing per-page tool contracts remain unchanged.
- Release stabilization fixes a native Mounted URLs navigation failure by
  acquiring read access for snapshot freshness checks, including mouse callbacks
  that run without an implicit read lock. Pending edits still reject stale rows.

## Verification

The final candidate passes **2,317 normal tests**, **eight actual MCP host tests**,
**20 release-checker tests**, packaging/project/structure checks and Compatible
binary verification. The verifier reports five deprecated and six experimental API usages; the
synchronous freshness guard adds one ReadAction.run deprecation to the previous
four. The final ZIP JAR matches both isolated installations: a repeated
native Preview 2 upgrade, and a fresh profile with MCP excluded. Native checks
cover editor following, root HTML navigation, missing-pair findings, paired rename
with preview/Undo during stabilization, read-lock-free route double-click after
the fix, Spring dependency candidates and the plain-test preview. All nine tools
are visible; Codex CLI 0.166.0 and Claude Code 2.1.317 successfully invoke routes
through the graphical server. These are isolated profiles, not a normal-user
profile installation or a full application-accuracy study.

This GitHub prerelease provides the verified ZIP and SHA256SUMS.txt for feedback
before the final 0.1.0 release.

## Candidate scope and feedback

Verified targets are IntelliJ IDEA **2026.2.3**, build **IU-262.10968.63**, and
Wicket **10.11.0** fixtures. Other combinations remain unverified. Analysis is
static and bounded; DECLARED routes are source observations, not a complete
active runtime URL table. Mapper variables/factories/wrappers/named subclasses,
root mapper mutations and package/resource registrations remain future work.
Spring candidates do not establish runtime profile activation or bean wiring.
Test scaffolds require review and application-specific adaptation.

The bundled MCP host's wire cancellation/session-expiry limitation remains:
requests are bounded by WicketLens's 30-second deadline; reconnect after an
expired session. Connected agents may send tool responses to their model
provider. The full real-application accuracy/performance study remains deferred. A limited
source-only smoke check of five external application pages returned bounded,
partial graphs with explicit uncertainty for custom framework patterns; it does
not establish reconstruction accuracy or complete real-project support.

When reporting a problem, include the IDE and Wicket versions, the affected
feature, reproduction steps, and a minimal Java/HTML example with private data
removed. Report confidence/coverage problems as well as exceptions. For editor
operations, include whether Preview and Undo behaved as expected.

Candidate verification results and installation/client checks are recorded in
[the release checklist](../release-checklist.md) and
[implementation notes](../acceptance.md). A release candidate invites feedback;
it does not claim complete Wicket language or runtime coverage.
