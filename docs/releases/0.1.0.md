# WicketLens 0.1.0

The first final release brings Wicket-aware component exploration and editor
tools to IntelliJ IDEA, with optional Spring analysis, WicketTester planning,
Mounted URLs and nine read-only MCP tools.

## Installation and upgrade

Download **wicketlens-0.1.0.zip** and **SHA256SUMS.txt** from this release's Assets.
In IntelliJ IDEA, open **Settings → Plugins → ⚙ → Install Plugin from Disk…**,
select the ZIP without extracting it, and restart if prompted. The same steps
upgrade RC 1 or an earlier preview. No local build or separate JDK installation
is required. WicketLens is not on JetBrains Marketplace yet.

## Included features

- A component hierarchy with source details, search/status filters, subtree focus,
  finding traversal, editor following and Java/HTML navigation.
- Parent-aware ID matching, inspections, completion, configurable coloring,
  conservative paired rename and supported counterpart quick fixes, with preview
  and Undo.
- Bounded source analysis for helpers, factories, superclass setup, initialization,
  immutable provider state, computed IDs and agreeing conditional paths. Queue
  placement and repeater templates retain their scope and uncertainty.
- Optional Wicket–Spring inspections, source bean-name completion/navigation,
  injected-dependency context, profile conditions and generic FactoryBean candidates.
- Plain-Wicket and Spring WicketTester planning/scaffolds, plus runnable demos
  showing agent adaptation, meaningful assertions and regression/restoration checks.
- A project-wide Mounted URLs view for reviewed `mountPage` and inline
  `MountedMapper` registrations, including source init inheritance and closed
  no-argument helpers.
- Nine read-only MCP tools sharing the same analyzers and snapshots: connectivity,
  page structure, validation, component context, injected dependencies, Spring
  findings, both test plans and routes.

## Changes since RC 1

The feature set and production classes are retained from RC 1. Final release
metadata identifies version **0.1.0**. The fixtures and all four Maven demos now
use **Wicket 11.0.0**, with **Spring 7.0.9**, **Servlet 6.1.0** and **JUnit 6.1.3**.
Demos target **Java 21**; building WicketLens itself still requires **Java 25**.
The Wicket 11 constructor, initialization, markup, queue/repeater, route and Spring
contracts were reviewed before upgrading the baseline. Wicket and Spring remain
project/fixture dependencies and are not bundled in the plugin.

## Verification and limits

The final version passes **2,317 normal plugin tests**, **eight actual MCP host
tests**, **20 release-checker tests**, plugin packaging/project/structure checks
and **Compatible** binary verification. The verifier retains five deprecated and
six experimental API notices. All four Maven demos compile; the runnable plain
and Spring demos pass three and eight tests respectively, including separate
deliberate regression/restoration checks.

The verified IDE is **IntelliJ IDEA 2026.2.3 / IU-262.10968.63**. Current automated
fixtures and demos use **Wicket 11.0.0**. The original RC 1 graphical installation,
editor and nine-tool MCP checks used Wicket 10.11.0, Codex CLI 0.166.0 and Claude
Code 2.1.317. That historical evidence is retained for the identical production
classes; it is not a new final-version graphical walkthrough. Other IDE, client
and framework combinations remain unverified.

Analysis is static, bounded and partial. Dynamic or unsupported setup retains
uncertainty. Route declarations do not establish a complete active runtime URL
table; mapper variables/factories/wrappers/subclasses, root mapper mutations and
package/resource registrations remain future work. Spring candidates do not
establish active profiles or runtime wiring. Test scaffolds require review and
application-specific adaptation.

The bundled MCP host still has its documented wire-cancellation/session-expiry
limitation: work is bounded by WicketLens's 30-second deadline; reconnect after
an expired session. Connected agents may send tool responses to their model
provider. The full real-application accuracy/performance study remains deferred.
The limited five-page source smoke check does not establish that target.
